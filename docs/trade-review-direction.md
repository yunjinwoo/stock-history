# 매매 복기 및 개선 방향

## 1. 문서 목적

이 프로젝트는 거래 내역을 저장하는 매매일지를 넘어, 매매의 이유와 실행 결과를 비교하고 반복되는 실수를 찾아 다음 매매를 개선하는 관리 도구를 지향한다.

핵심 질문은 다음과 같다.

1. 왜 이 종목을 샀는가?
2. 진입 전에 세운 계획은 무엇이었는가?
3. 계획대로 실행했는가?
4. 수익 또는 손실의 원인은 무엇이었는가?
5. 다음 매매에서 무엇을 바꿀 것인가?

따라서 향후 기능은 단순한 거래 수와 수익금보다 **매매 이유, 계획 준수, 행동 패턴, 개선점**을 분석하는 방향으로 확장한다.

### 핵심 제약조건: 기록 습관을 방해하지 않는다

분석 기능을 추가하더라도 입력 부담 때문에 기록을 중단하게 만들면 안 된다. 개인용 매매일지에서는 기능의 완성도보다 실제 사용 지속성이 우선이다.

- 진입 시 필수 입력은 최대 2~3개로 제한한다.
- 나머지는 선택 입력, 자동 계산, 기본값으로 처리한다.
- 진입 시 입력과 매도 완료 후 복기 입력을 분리한다.
- 상세 복기는 사용자가 원할 때만 펼칠 수 있게 한다.
- 기본 기록 시간은 10~20초 이내를 목표로 한다.

---

## 2. 현재 프로젝트의 역할

현재 프로젝트는 다음 정보를 기록하고 보여준다.

- 분할 매수·매도 내역
- 종목별 보유 기간과 손익
- 목표가·손절가·계획 보유기간
- 매도 후 코멘트와 매매 점수
- 계좌별·종목별 손익
- 일별·주별·월별 손익 차트
- 종목 태그와 별도 메모
- 거래 이미지 및 가격 차트

이 기능들은 향후 복기 분석의 기반 데이터로 활용한다.

## 3. 제품 방향성

### 3.1 기록보다 의사결정 중심

거래 결과만 기록하지 않고, 매매 당시의 판단과 계획을 함께 남긴다.

```text
진입 전 계획 → 실제 실행 → 결과 → 복기 → 다음 행동 규칙
```

### 3.2 수익과 매매 품질을 분리

수익이 났다고 항상 좋은 매매인 것은 아니다. 계획을 지켰는지, 위험을 관리했는지, 우연한 수익인지 구분한다.

- 결과: 실제 손익과 수익률
- 과정: 진입·청산 계획 준수 여부
- 행동: 충동매매, 손절 지연, 조기 매도 여부

### 3.3 통계는 행동 개선에 사용

통계 화면은 단순히 숫자를 보여주는 데 그치지 않고, 사용자가 다음 매매에서 적용할 수 있는 결론을 제공해야 한다.

좋은 분석의 예:

- 돌파 매매의 승률은 높지만 손익비가 낮다.
- 계획 보유기간을 초과한 거래의 평균 손익이 낮다.
- 손절을 지킨 거래는 손실이 작고, 손절을 미룬 거래는 손실이 크다.
- 특정 시간대 또는 특정 진입 이유에서 반복적으로 손실이 발생한다.

## 4. 핵심 기능 요구사항

### 4.1 진입 전 매매계획

거래 입력 시 다음 항목을 기록할 수 있어야 한다.

- 매매 전략: 돌파, 눌림목, 추세추종, 가치투자 등
- 진입 이유: 실적, 수급, 뉴스, 차트, 테마, 저평가 등
- 진입 확신도
- 예상 시나리오
- 시나리오가 틀렸다고 판단할 조건
- 투자 금액 또는 포지션 비중
- 계획 목표가
- 계획 손절가
- 계획 보유기간
- 계획상 최대 손실금액

자유 메모는 보조 수단으로 사용하고, 통계가 필요한 항목은 선택형 값이나 태그로 관리한다.

단, 모든 항목을 한 번에 요구하지 않는다. 1차 MVP에서 진입 시 필수로 받을 값은 다음 중 2~3개로 제한한다.

- 진입 이유 1개
- 목표가 또는 손절가
- 계획 보유기간

전략, 확신도, 예상 시나리오, 무효조건, 투자 비중 등은 선택 입력으로 제공한다. 카카오톡 파싱 거래는 파싱 결과를 우선 저장할 수 있어야 하며, 추가 계획 입력은 저장 후 나중에 보완할 수 있어야 한다.

### 4.2 실제 실행 기록

기존 체결 내역을 바탕으로 계획과 실제를 비교할 수 있어야 한다.

- 실제 진입 시각과 평균 매수가
- 실제 청산 시각과 평균 매도가
- 분할 매수·매도 횟수
- 목표가 도달 여부
- 손절가 도달 또는 이탈 여부
- 계획 보유기간 초과 여부
- 잔여 보유 수량
- 수수료·세금 반영 후 순손익

#### 입력 시점 분리

입력 항목은 매매 생애주기에 따라 나눈다.

| 시점 | 기본 입력 | 선택 입력 |
|---|---|---|
| 매수 시 | 진입 이유, 목표가·손절가 중 필요한 값 | 전략, 확신도, 예상 시나리오, 감정 |
| 보유 중 | 기존 체결 내역 | 계획 수정 메모 |
| 최종 매도 후 | 청산 이유, 복기 한 줄 | 잘한 점, 아쉬운 점, 다음 행동, 감정 |
| 주간·월간 복기 | 기간 요약, 다음 규칙 | 반복 실수 상세 분석 |

최종 매도 후에는 별도 복기 팝업을 열어 최소 입력만 받고, 상세 항목은 접힌 상태로 제공한다. 매매 입력 모달에 모든 복기 필드를 넣어 초기 입력 화면이 복잡해지지 않도록 한다.

### 4.3 청산 후 복기

거래가 완료되면 다음 내용을 기록할 수 있어야 한다.

- 청산 이유: 목표가, 손절, 추세 이탈, 기간 만료, 공포, 욕심 등
- 실제 결과에 대한 설명
- 잘한 점
- 아쉬운 점
- 반복된 실수
- 다음에 유지할 행동
- 다음에 바꿀 행동
- 매매 품질 점수
- 계획 준수 점수

1차 MVP에서는 `청산 이유`와 `복기 한 줄`만 기본 입력으로 둔다. 잘한 점·아쉬운 점·반복 실수·유지 행동·변경 행동은 선택 입력으로 두고, 정기 복기 화면에서 나중에 작성할 수 있게 한다.

### 4.4 계획 대비 실행 평가

시스템이 다음 결과를 자동 계산한다.

- 계획 보유기간 이내 여부
- 목표 수익률 달성 여부
- 손절 기준 준수 여부
- 계획대로 청산했는지 여부
- 계획 수익률 대비 실제 수익률 차이
- 계획상 위험 대비 실제 손익

#### 자동 계산 기준

분할 매수·분할 매도가 있는 거래도 동일한 기준으로 계산할 수 있도록 다음 규칙을 사용한다.

- **목표가 도달 여부**: 실제 매도 체결 중 하나라도 목표가 이상이면 `도달`로 판정한다.
- **손절가 도달 여부**: 실제 매도 체결 중 하나라도 손절가 이하이면 `도달`로 판정한다.
- **최종 결과**: 전체 매도 수량의 가중평균 매도가를 기준으로 계산한다.
- **최종 목표 달성 여부**: 최종 가중평균 매도가가 목표가 이상인지 별도로 계산한다.
- **보유기간**: 최초 매수일에서 최종 매도일까지 계산한다.
- **부분매도 거래**: 중간 체결의 목표가·손절가 도달 여부와 최종 결과를 분리해서 표시한다.

일부 물량만 목표가에 도달한 경우에도 `목표가 도달`과 `최종 목표 달성`을 혼동하지 않는다.

예시:

```text
계획: 1주일 보유 / 목표 +10% / 손절 -5%
실제: 18일 보유 / 수익 +3%
평가: 보유기간 초과 / 목표 미달 / 수익 거래
복기: 수익은 났지만 계획을 지키지 못한 거래
```

## 5. 추천 데이터 분류

### 5.0 종목 태그와 거래 태그의 구분

기존 `StockMaster.tags`와 새로 추가하는 진입 이유·청산 이유·감정 태그는 서로 다른 데이터다.

| 구분 | 의미 | 예시 |
|---|---|---|
| 종목 태그 (`StockMaster.tags`) | 종목의 비교적 고정된 속성 | 반도체, 대형주, 배당주 |
| 거래 태그 (`Trade`) | 특정 거래를 실행한 당시의 상황 | 돌파, 뉴스, FOMO, 공포 |

혼동을 피하기 위해 거래 필드 이름은 `symbolTags`와 겹치지 않도록 `entryReason`, `exitReason`, `emotionBefore`, `emotionAfter`처럼 구체적으로 지정한다. 초기에는 진입 이유·청산 이유를 각각 단일 선택값으로 시작하고, 여러 개 선택은 사용 패턴을 확인한 뒤 검토한다.

### 5.1 진입 이유 태그

- 추세
- 돌파
- 눌림목
- 실적
- 수급
- 뉴스
- 테마
- 저평가
- 배당
- 충동매매
- 물타기

### 5.2 청산 이유 태그

- 목표가 도달
- 손절
- 추세 이탈
- 계획 기간 만료
- 공포
- 욕심
- 조기 매도
- 다른 종목으로 이동
- 현금 필요
- 실수

### 5.3 감정 상태

- 차분함
- 확신
- 불안
- FOMO
- 복수심
- 조급함
- 피로
- 스트레스

감정 데이터는 선택 입력으로 두되, 충동매매와 손실의 상관관계를 분석할 수 있도록 한다.

## 6. 핵심 분석 지표

현재 총손익·승률·평균 수익률에 다음 지표를 추가한다.

### 6.1 기본 성과

- 평균 이익
- 평균 손실
- 손익비
- 기대값
- 최대 연속 승리
- 최대 연속 손실
- 최대 낙폭
- 순손익

### 6.2 계획 실행 성과

- 계획 준수율
- 목표가 도달률
- 손절 준수율
- 계획 보유기간 초과율
- 계획 수익률 대비 실제 수익률
- 계획을 지킨 거래와 어긴 거래의 평균 손익 비교

### 6.3 행동 패턴

- 전략별 승률·손익·기대값
- 진입 이유별 성과
- 청산 이유별 성과
- 감정 상태별 성과
- 요일별 손익
- 시간대별 손익
- 충동매매 손실 비중
- 조기 매도 후 추가 상승한 거래 비율

### 6.4 R 배수

손절 기준을 위험 단위로 사용한다.

```text
1R = 계획상 손절 시 발생하는 손실금액
R 배수 = 실제 순손익 / 1R
```

1R은 매매 계획을 평가하기 위한 값이므로 **계획 시점의 값으로 고정**한다. 분할 매수로 실제 평균단가가 바뀌더라도 이미 기록된 계획 위험을 재계산하지 않는다.

권장 산식:

```text
계획 1R = (계획 평균진입가 - 계획 손절가) × 계획 수량
실제 R = 실제 순손익 ÷ 계획 1R
```

계획 평균진입가나 계획 손절가가 없는 기존 거래는 최초 평균매수가와 실제 매도 수량을 사용해 추정한다. 추정값은 계획값과 구분해서 표시한다.

추가 지표:

- 평균 R
- 승리 거래 평균 R
- 패배 거래 평균 R
- 전략별 평균 R
- 월별 누적 R

수익금이 아닌 위험 대비 결과를 비교하기 때문에 투자금이 다른 거래도 공정하게 비교할 수 있다.

## 7. 복기 화면 방향

통계 페이지에 별도의 복기 영역을 추가하거나 `/reviews` 페이지를 만든다.

### 기간 선택

- 이번 주
- 이번 달
- 지난달
- 직접 기간 설정

### 자동 요약

- 총 거래 수
- 총 순손익
- 승률
- 평균 이익·손실
- 손익비
- 계획 준수율
- 가장 잘한 전략
- 가장 손실이 큰 행동
- 반복되는 실수

### 사용자 작성 영역

- 이번 기간 잘한 점
- 가장 아쉬운 매매
- 반복된 실수
- 다음 기간에 지킬 규칙 1~3개
- 하지 않을 행동

복기 완료 여부와 작성일을 관리하여 복기를 미룬 거래와 기간을 확인할 수 있게 한다.

## 8. 데이터 모델 확장 후보

현재 `Trade`에 이미 계획·목표·손절·점수·청산 코멘트가 있으므로, 1차 구현에서는 기존 구조를 최대한 활용한다.

### Trade에 추가를 검토할 필드

```text
strategy              // 매매 전략
entryReasons          // 진입 이유 태그
exitReasons           // 청산 이유 태그
emotionBefore         // 진입 전 감정
emotionAfter          // 청산 후 감정
confidenceScore       // 진입 확신도
processScore          // 계획 준수 점수
isImpulseTrade        // 충동매매 여부
plannedRiskAmount     // 계획상 위험 금액
buyFee                // 매수 수수료
sellFee               // 매도 수수료
tax                   // 세금
```

### 별도 테이블을 검토할 데이터

복기 데이터가 많아지면 Trade에 계속 필드를 추가하기보다 별도 테이블로 분리한다.

```text
TradeReview
- id
- tradeId
- goodPoint
- badPoint
- lesson
- nextAction
- reviewedAt
```

```text
PeriodReview
- id
- periodStart
- periodEnd
- summary
- repeatedMistakes
- rulesToKeep
- rulesToChange
- createdAt
```

전략·이유·감정은 초기에 문자열 또는 JSON으로 시작할 수 있지만, 통계를 적극적으로 사용할 시점에는 정규화된 태그 테이블을 검토한다.

1차 구현에서는 기존 `plannedHoldingPeriod`, `targetPrice`, `stopLossPrice`, `exitComment`, `tradeScore`를 우선 활용한다. 실제 사용률이 확인된 뒤 거래 이유·감정·점수 필드를 추가한다.

## 9. 개발 우선순위

### Phase 0 — 입력 UX 검증

기능 개발 전에 실제 입력 흐름을 먼저 검증한다.

- 기존 직접 입력·카카오톡 입력 흐름 유지
- 진입 시 필수 항목을 2~3개로 제한
- 최종 매도 후 별도 복기 팝업 제공
- 상세 필드는 접힘 상태로 제공
- 신규 입력에 걸리는 시간 측정
- 일정 기간 실제 사용 후 입력률 확인

완료 기준은 필드가 모두 존재하는 것이 아니라, 사용자가 거래를 계속 기록하는 것이다.

### Phase 1 — 최소 복기 MVP

- 진입 이유 1개
- 기존 목표가·손절가·계획 보유기간 활용
- 청산 이유 1개
- 매도 완료 후 복기 한 줄
- 계획 대비 결과 자동 표시
- 계획 준수율 통계
- 수수료·세금 반영은 별도 작업으로 분리

### Phase 2 — 성과·행동 분석

- 전략별 통계
- 진입·청산 이유별 통계
- 계획 준수율
- 손익비·기대값
- 연속 손실·최대 낙폭
- 요일·시간대별 분석
- 복기 미완료 거래 목록

### Phase 3 — 정기 복기

- 주간·월간 복기 페이지
- 자동 요약
- 반복 실수 집계
- 다음 기간 행동 규칙 기록
- 복기 완료 이력

### Phase 4 — 고급 분석

- R 배수
- MFE·MAE
- 벤치마크 비교
- 과거 가격 기반 매매 시점 분석
- 반복 패턴 자동 알림

Phase 3과 Phase 4는 별도 제품 수준으로 확장될 수 있으므로, Phase 1의 사용성과 효과가 검증된 경우에만 진행한다.

### 9.1 1차 MVP 범위

실제 착수 시 첫 번째 목표는 다음으로 한정한다.

- 매수 입력 시간이 30초 이내일 것
- 진입 이유를 한 번의 선택으로 남길 수 있을 것
- 매도 완료 후 복기 한 줄을 남길 수 있을 것
- 계획 대비 실제 결과를 자동으로 보여줄 것
- 계획을 지킨 거래와 어긴 거래를 비교할 수 있을 것

초기에는 감정 기록, R 배수, MFE·MAE, 벤치마크, 자동 패턴 알림을 구현 범위에서 제외한다. 실제 사용자가 반복해서 작성하는 항목이 확인된 뒤 확장한다.

## 10. 완료 기준

다음 질문에 화면에서 답할 수 있으면 1차 목표를 달성한 것으로 본다.

- 내가 가장 잘하는 매매 전략은 무엇인가?
- 어떤 진입 이유에서 수익이 나는가?
- 어떤 상황에서 손실이 반복되는가?
- 계획을 지킨 거래의 성과는 어떤가?
- 손절을 미룬 거래의 손실은 얼마나 커지는가?
- 수익이 났지만 과정이 나빴던 거래는 무엇인가?
- 다음 매매에서 지켜야 할 규칙은 무엇인가?

이 프로젝트의 최종 목표는 거래를 많이 기록하는 것이 아니라, 기록을 통해 사용자의 매매 의사결정과 습관을 지속적으로 개선하는 것이다.
