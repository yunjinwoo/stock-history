### 2-1. 코인 복기(타임라인) 뷰 (PR #61)

주식 `TradeTimeline`과 동일한 UX를 코인에도 적용한 `CoinTimeline.tsx` 신규 작성.
- 코인은 계좌/시장구분 개념이 없어 좌측 필터에서 해당 항목 제외, 익절·손절 + 수익률 구간 필터만 유지
- 상세보기 토글로 가격 차트 + 매수/매도 내역 펼침은 주식과 동일

**주/월별 토글 (주식·코인 공통)**
- 기존엔 4주 컬럼 고정이었는데, 거래 빈도가 낮은 종목은 주별 컬럼에 빈 칸이 많아 월별 그룹 옵션 추가
- `groupBy: 'week' | 'month'` 상태로 컬럼 생성 로직 분기

**수익률 구간별 테두리 두께 차등**
```
±20% 이상 → border-l-8 (진하고 두껍게)
±10~20%   → border-l-4
그 외      → border-l-2
```
기존엔 색상만 진하기로 구분했는데, 두께까지 더해 한눈에 크기 인지가 쉽도록 개선.

### 2-5. 매매 점수(1~5점) (미커밋, PR #65~68 이후)

**배경**: 매매 계획(목표가/손절가) 대비 실제 결과를 사후에 스스로 채점해 복기에 활용하고 싶다는 요구.

**스키마**
```prisma
model Trade {
  tradeScore Int?
}
model CoinTrade {
  tradeScore Int?
}
```

**자동 산정 로직** (`lib/utils.ts`)
```ts
export function calcAutoTradeScore(profitRate: number): number {
  if (profitRate > 2) return 4
  if (profitRate <= 0 && profitRate >= -5) return 2
  return 3
}
```
- 수익률 +2% 초과 → 4점, 손실 0~-5% 이내 → 2점, 그 외(큰 손실 또는 애매한 구간) → 3점 기본값
- 5점(최고)·1점(최악)은 자동 산정하지 않고 사용자가 직접 입력해야 하는 값으로 남겨둠 — "자동으로는 극단값을 주지 않는다"는 의도

**TradeModal / CoinModal**
- 매도 완료(`isCompleted`)된 거래에서만 점수 입력 UI 노출 (보유중에는 최종 수익률이 확정되지 않아 비활성)
- `scoreTouched` 상태로 사용자가 수동 수정했는지 추적 — 폼이 열릴 때 기존 점수가 있으면 `touched=true`로 시작해 자동 재계산이 사용자 입력을 덮어쓰지 않게 함
- 수익률이 바뀔 때(매도 항목 수정 등) `scoreTouched`가 false면 `calcAutoTradeScore`로 재계산해 자동 채움

**TradeCard / CoinHistory**: 카드·목록에 점수 배지 표시

### 2-6. 카드형 뷰 매매 시나리오 계산기 (미커밋, DB 저장)

**배경**: 보유중 종목을 분할 매도할 때 "얼마에 몇 주씩 팔면 목표 수익에 도달하는지"를 매번 계산기 앱이나 메모장에 따로 계산하던 걸 카드 안에서 바로 처리하고 싶어서 추가.

**스키마**
```prisma
model TradeScenario {
  tradeId      String @id   // Trade와 문자열로만 연결 (FK 없음, cascade 없음)
  currentPrice String?
  budget       String?
  targetProfit String?
  rowsJson     String       // 시나리오 행 배열을 JSON 문자열로 저장
  createdAt    String
  updatedAt    String
}
```
`SimEntry`와 마찬가지로 Trade FK 관계를 걸지 않은 이유: 시나리오는 어디까지나 계획용 스크래치 데이터라 Trade 삭제 시 자동 정리되지 않아도 무방하다고 판단.

**API**: `app/api/trade-scenarios/[tradeId]/route.ts`
- `GET` — 저장된 시나리오 조회 (없으면 `null`)
- `PUT` — `upsert`로 저장 (전체 rows를 JSON으로 직렬화해 교체)
- `DELETE` — `deleteMany`로 초기화

**TradeCard.tsx 핵심 로직**
```ts
function calcScenarioRow(row: ScenarioRow, budget: number) {
  const qty = budget > 0 ? Math.floor(budget / buy) : 0
  // 매도가·수량 기준 부분수익 계산
}
```
- 카드를 펼치면(`scenarioOpen`) 최초 1회 `GET /api/trade-scenarios/{tradeId}`로 저장된 값을 불러옴 (`scenarioLoaded` 가드로 중복 호출 방지)
- 기본값: 현재가는 평균매수가, 여유자금은 500,000원, 목표 전체수익은 투자금(원가)의 50%
- "현재가 불러오기" 버튼으로 `/api/stock-price` 조회 결과를 현재가 입력에 채움 (PR #67의 현재가 연동 인프라 재사용)
- **자동 행 추가**: 목표 전체수익에 도달할 때까지 필요한 행 수를 계산해 한 번에 추가
  ```ts
  const currentTotal = scenarioRows.reduce((sum, r) => sum + (calcScenarioRow(r, budget)?.profit ?? 0), 0)
  // (target - currentTotal) 를 행당 예상 수익으로 나눠 neededRows 산출 후 일괄 추가
  ```
- 행 추가 후 해당 행으로 `scrollIntoView({ behavior: 'smooth', block: 'center' })`로 자동 스크롤
- 저장 버튼 클릭 시 `PUT`으로 전체 상태 저장, "저장됨" 표시는 잠깐 노출 후 사라짐
- "초기화" 시 `DELETE` 호출 + 로컬 상태를 기본값으로 리셋

## 3. 패턴 정리

- **Trade FK 없는 보조 테이블 패턴**: `SimEntry`, `TradeScenario`처럼 "계획/시뮬레이션용 스크래치 데이터"는 Prisma `@relation` 없이 `tradeId` 문자열만 저장 — Trade 삭제 시 cascade 삭제가 안 되는 트레이드오프를 감수하고 스키마를 단순하게 유지
- **자동 계산값 + 수동 덮어쓰기 허용 패턴**: 목표가/손절가(PR #65)에 이어 매매 점수도 "자동 산정 → `touched` 플래그로 사용자 수정 보존" 패턴을 재사용
- **행 배열을 JSON 문자열로 저장**: 시나리오처럼 개수가 가변적이고 구조가 자주 바뀔 수 있는 데이터는 별도 테이블 대신 `rowsJson` 하나로 직렬화해 스키마 마이그레이션 부담을 줄임
- **CLAUDE.md ↔ AGENTS.md 동기화**: 프로젝트 규칙 문서를 두 파일로 유지하는 대신 항상 함께 수정해야 함 (자동 동기화 스크립트 없음, 수동 확인 필요)
